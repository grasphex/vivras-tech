firewalld｜同じ80番でも、zoneで結果が変わる

通信を許可するかは、まず適用するzone（ルールのまとまり）を選び、その中のポート・通信方式で決まる。違うzoneへ設定しても通りません。

2026-11-15 · 新卒〜3年目SE · 動く図解

1. まず結論：zoneによって許可が違う

firewalldは、Linuxへ届く通信に対し、適用するzoneを決め、そのzoneのルールで通信を判断するための設定管理サービスです。

なぜ必要？ 同じサーバーでも接続するネットワークによって、許可したい通信が異なるためです。たとえば社内向けの接続口ではSSHを許可し、公開向けの接続口ではWeb通信だけを許可する、といった管理ができます。

2. 通信の登場人物を整理

パケット
ネットワーク上で送受信されるデータの単位。通信先IP・ポートなどの情報を含みます。
IPアドレス
ネットワークで通信先を特定するための番号。
ポート番号
受信した通信をどのサービスへ渡すかを区別する番号。例：80はHTTPによく使われます。
TCP / UDP
通信方式の区別。同じ80番でも80/tcpと80/udpは別の条件です。
インターフェース
Linuxがネットワークと接続する口。例：eth0。
zone
通信の入口に適用するルールのまとまり。内部向け・公開向けなどを区別します。
service / port
serviceは複数の通信条件を名前で定義したもの。portは番号とTCP/UDPを直接指定する方法です。

3. 受信した通信を判定する順序

① 受信サーバーが新規パケットを受け取ります。
② zone接続元やインターフェースの割当から適用zoneを決めます。割当がなければデフォルトzoneを使います。
③ 照合そのzoneの許可ルールと、宛先ポート・プロトコルを比較します。
④ 判定教材で定義したルールに合えば通過、合わなければ拒否となります。

5. 設定を確認・変更する

# firewalldの起動状態
sudo firewall-cmd --state
# 実際に使われるzoneと接続口
sudo firewall-cmd --get-active-zones
# internalの設定（例）
sudo firewall-cmd --zone=internal --list-all
# 変更例：internalにHTTPを永続的に許可
sudo firewall-cmd --permanent --zone=internal --add-port=80/tcp
# 永続設定を実行時に反映（既存のruntimeのみの設定には注意）
sudo firewall-cmd --reload
# 反映後の確認
sudo firewall-cmd --zone=internal --list-ports

出力のどこを見る？

--get-active-zonesはインターフェースや送信元がどのzoneに紐付いているかを示します。--list-allのservicesとportsに設定済みの許可が出ます。--permanentによる変更は直ちに実行時へ反映されず、--reloadで反映します。注：設定変更は管理用通信を切断する危険があるため、実機では影響を確認してから操作してください。

出力はOSや設定によって異なります。上記はコマンド例であり、実機実行結果の転載ではありません。

6. よくある誤解

zone＝通信先の場所？
いいえ。ここでは受信通信に適用するルールセットです。
80/tcpを開ければ80/udpも通る？
いいえ。番号とプロトコルの両方を照合します。
firewallの許可＝必ずサービスに接続できる？
いいえ。受信アプリが待受しているか、経路や別の制御があるかも別に確認します。

7. 3問で理解を確認

Q1. internalに22/tcpだけ許可。80/tcpは通る？

答え：通りません。許可条件に80/tcpがないためです。

Q2. publicに80/tcpを追加したらinternalにも反映される？

答え：反映されません。zoneはそれぞれ独立したルールを持ちます。

Q3. --permanentで許可を追加し、まだreloadしていない。実行中の設定は変わる？

答え：通常は変わりません。永続設定と実行時設定は別です。
