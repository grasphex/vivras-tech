ルートファイルシステムとread-only再マウントを図解で理解する

「ルートをマウントするって、ディスクにひもづけること？」から出発し、起動時にread-onlyで始める理由と、read-writeへ再マウントする意味までつなげます。

2026-11-14 · 基礎〜標準 · 図解＋操作デモ

1. 結論：マウントは「ファイルシステムをLinuxの木構造につなぐ」こと

Linuxでは、ディスクやパーティション上のファイルシステムを、ディレクトリツリー上の場所に接続する操作をマウントと呼びます。

ルートファイルシステムをマウントするとは、たとえば /dev/sda1 上のファイルシステムを、Linuxのディレクトリ構造の一番上である / に結びつけることです。

ディスク側
/dev/sda1
ext4などのファイルシステム
→
Linuxから見える場所
/ ├ /etc ├ /usr ├ /var └ /home

ポイント：/dev/sda1 と / は同じ名前ではありません。前者は「どのデバイスか」、後者は「Linuxのどこに見せるか」です。

2. 前提知識：root=、ro、rwは何を指定している？

起動時、ブートローダはカーネルに起動パラメータを渡せます。たとえば次のような指定です。

root=/dev/sda1 ro

root=/dev/sda1 は「実際のルートファイルシステムとして使うデバイス」を指定します。ro は、そのルートファイルシステムを最初はread-only（読み取り専用）で扱う指定です。rw はread-write（読み書き可能）です。

3. なぜ最初はread-onlyなのか

伝統的なLinuxの起動では、ルートファイルシステムを最初はread-onlyでマウントし、ファイルシステムの整合性確認を安全に行える状態にします。書き込みが行われない状態なら、fsck などの整合性チェックが対象を変化させずに扱いやすくなります。

起動
→
/ を ro でマウント
→
確認
→
rwへ

現代のsystemd環境では、fsckやマウント処理の具体的な順序・担当はディストリビューションや構成によって異なります。ただし、ro の目的として「整合性確認のため、書き込みを止めた状態を作る」という考え方はLinuxのbootparam(7)にも記載されています。

5. 再マウントとは「同じ接続の条件を変える」こと

すでに / に接続されているファイルシステムを、別の場所へ付け替えるのではありません。同じデバイス・同じマウントポイントのまま、マウント条件を変更します。

# ルートファイルシステムをread-writeへ再マウント
sudo mount -o remount,rw /

# 逆にread-onlyへ再マウント
sudo mount -o remount,ro /

mount(8) の説明でも、remount は「すでにマウント済みのファイルシステムのマウントフラグを変更する」操作で、デバイスやマウントポイント自体は変更しないとされています。

部分意味
mountファイルシステムのマウント操作
-oオプション指定
remountマウント済みのものを再マウント
rwread-writeにする
/対象のマウントポイント

一言で：mount -o remount,rw / は「今 / として使っているファイルシステムを、読み書き可能な条件に変えて」と読むと理解しやすいです。

6. 誤解しがちな点

「/ をマウントする」＝ディレクトリそのものをディスクへコピーする、ではありません。 ディスク上のファイルシステムを / という場所から参照できるように接続します。

再マウント＝別のディスクへつなぎ直す、でもありません。 remount,rw では、同じファイルシステムの読み書き条件を変更します。

普段の起動で利用者が手動実行するわけではありません。 通常の起動処理では必要なマウントや状態変更は起動システムが処理します。手動の mount -o remount,rw / は、レスキューや保守などで利用することがあります。

7. 理解度チェック

Q1. 「/dev/sda1を/にマウントする」とは何をしている？

答え：/dev/sda1 上のファイルシステムを、Linuxのディレクトリツリーの / から参照できるように接続しています。

Q2. root=/dev/sda1 の root は何を指定する？

答え：起動後にルートファイルシステムとして使うデバイスを指定します。

Q3. 起動時に最初はroでマウントする主な理由は？

答え：ファイルシステムへの書き込みを止めた状態で整合性確認を行えるようにするためです。

Q4. mount -o remount,rw / は別のディスクを/へ接続するコマンド？

答え：いいえ。すでに / にマウントされているファイルシステムを、read-writeの条件で再マウントします。
